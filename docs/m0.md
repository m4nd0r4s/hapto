# M0 — measure and verify

What `docs/SPEC-2.0.md` milestone M0 asked for: measure the rebuild model
before anything is built on it, confirm every **(verify)** claim about
kinemo, and decide the three open questions that depended on numbers.

| | |
|---|---|
| Date | 2026-10-31 |
| Machine | Apple M4 Pro, 14 cores; rustc 1.99.0; Node 26.13 |
| kinemo | pinned `4cbd012` |
| Benchmark | `crates/hapto-core/examples/m0_rebuild.rs` |

**This machine is faster than the spec's reference laptop** (M1 class) —
expect roughly 1.5× the times below there, more on the reference phone. The
projections in §3 apply that factor.

---

## 1. The decisions

| Question (SPEC-2.0 §26) | Decision | Because |
|---|---|---|
| 1. Is the reconciler needed? | **No.** Rebuild the scene from nothing on every change. | Building a scene costs 0.01–0.1 ms and layout 0.1–1.5 ms; raster is 75–95% of every frame. A reconciler saves the cheap part. Text and maths caches are already global in kinemo, so a fresh scene does not re-shape strings it has seen. |
| 2. Is a Canvas2D backend needed? | **Not now.** CPU raster plus progressive quality. Revisit only if a corpus figure misses budget in the M3 browser measurements. | Typical figures project to 3–5 ms in wasm on the reference laptop. The figures at risk are text-heavy ones, and those are bounded by a label budget (§3). |
| 3. How is maths typeset in figures and in prose? | **Natively, at build time, with kinemo-math (typst), and baked.** No typst in the browser, no KaTeX. | typst compiles to wasm, but takes the bundle from **1.3 MB to 11.4 MB brotli**. kinemo already supports baked layouts (`kinemo_math::baked::register`), which is how its own WASM player works. The consequence is that TeX in figures must be **static**: a live number is text beside it. |
| 4. Non-16:9 frames? | **Supported directly.** Set `config.frame_w`/`frame_h` to the canvas's aspect. | `FrameSize::scale` uses width only; with a matching `frame_h` the frame fills any aspect. No letterbox. |
| 5. Fonts and subsetting | **Subset, and drop faces nobody uses.** Target ≤ 0.5 MB brotli for fonts. | The four DejaVu faces are **1.03 MB of the 1.29 MB** brotli bundle. |
| — Heat maps | **A raster underlay, not batched paths.** | Batched paths cost 26 ms (desktop, native) **and draw visible seams** between cells. A raster underlay costs 5 ms and is seamless. |

## 2. Measurements

### 2.1 The rebuild model, native

Every frame builds a fresh kinemo `Scene` with literal props only, lays it
out, and rasterises it. 60 frames after 5 of warm-up, the value changing
every frame as a drag would. Milliseconds, p50 / p95.

| Size | Workload | Build | Layout + display list | Raster | **Total** |
|---|---|---|---|---|---|
| desktop 720×405 @2 | simple | 0.01 / 0.01 | 0.07 / 0.10 | 0.75 / 1.06 | **0.83 / 1.16** |
| | labels | 0.10 / 0.13 | 1.44 / 1.67 | 6.13 / 6.50 | **7.61 / 8.30** |
| | math | 0.01 / 0.02 | 1.25 / 1.30 | 1.28 / 1.39 | **2.53 / 2.67** |
| | heat (paths) | 7.68 / 8.23 | 1.56 / 1.75 | 16.32 / 17.59 | **25.42 / 27.48** |
| | heat (underlay) | 3.70 / 3.80 | 0.05 / 0.07 | 1.47 / 1.59 | **5.22 / 5.34** |
| | arrows (10 000) | 4.75 / 4.82 | 0.74 / 0.86 | 21.60 / 22.16 | **27.10 / 27.68** |
| phone 360×203 @2 | simple | 0.01 / 0.01 | 0.07 / 0.08 | 0.47 / 0.54 | **0.56 / 0.62** |
| | labels | 0.10 / 0.11 | 1.46 / 1.61 | 5.97 / 6.19 | **7.52 / 7.91** |
| | math | 0.01 / 0.02 | 1.06 / 1.13 | 0.99 / 1.09 | **2.02 / 2.13** |
| | heat (paths) | 2.17 / 2.24 | 0.49 / 0.53 | 4.96 / 5.23 | **7.63 / 8.00** |
| | heat (underlay) | 0.91 / 0.92 | 0.04 / 0.05 | 0.68 / 0.73 | **1.63 / 1.69** |
| | arrows (10 000) | 4.72 / 4.79 | 0.73 / 0.79 | 18.02 / 18.81 | **23.44 / 24.34** |

Workloads:

- **simple** — axes, a 400-point curve whose shape follows the value, three
  dots, ten labels of which four are live. A typical figure.
- **labels** — simple plus 200 labels, 100 of them new strings every frame.
  The worst case for text: every frame shapes 100 strings it has never seen.
- **math** — simple plus eight TeX formulas, two of them with a live number,
  so two are typeset anew every frame (natively, with typst).
- **heat (paths)** — a heat map at 4 CSS px cells, 64 levels, cells merged
  into one path per level: the batching rule as SPEC-2.0 first wrote it.
- **heat (underlay)** — the same heat map evaluated once per cell,
  interpolated bilinearly to full resolution, and composited under the scene
  rendered with a transparent background.
- **arrows** — one path of 10 000 segments. A stress test: the spec's
  default density (one arrow per 32 CSS px) gives about 260 arrows on a
  desktop figure, not 10 000.

### 2.2 The wasm penalty

The same figure (1.0's legacy `plot`) drawn natively and in wasm under Node,
whose V8 is the one Chrome runs:

| Size | wasm (Node) | native | factor |
|---|---|---|---|
| 1440×810 | 2.10 / 2.52 | 0.60 / 0.67 | **3.5×** |
| 720×406 | 0.93 / 1.03 | 0.15 / 0.18 | 6× (fixed overhead dominates a tiny frame) |

A browser benchmark in M3 replaces this estimate.

### 2.3 Bundle size

|---|---|---|---|
| `hapto_web_bg.wasm` today (no typst) | 4.99 MB | 1.98 MB | **1.29 MB** |

## 3. Projection onto the budgets

SPEC-2.0 §19.1 asks for ≤ 16 ms (laptop) and ≤ 33 ms (phone) per
interaction frame. Native time × 3.5 (wasm) × 1.5 (reference laptop vs this
machine):

| Workload | Projected laptop, desktop size | Verdict |
|---|---|---|
| simple | ~4.4 ms | well inside |
| math, baked | ~3 ms (no typesetting at runtime) | well inside |
| heat (underlay), upscaled in wasm | ~27 ms | **over** — see below |
| labels (200, 100 new per frame) | ~40 ms | **over** — see below |
| arrows at default density (~260) | small; 10 000 is ~140 ms | inside at the spec's density |

Two consequences for the spec:

1. **The heat-map underlay belongs in the browser's compositor, not in
   wasm.** The expensive part of the underlay above is the bilinear upscale
   to full resolution, done per pixel in Rust. In the browser, hapto hands
   over only the cell grid (e.g. 180×101 RGBA) and the page draws it with
   `drawImage` and image smoothing into a canvas **under** the figure's
   transparent canvas. The GPU does the interpolation and the compositing;
   wasm does the cell evaluation (~1 ms) only. Native renders (`hapto
   render`, fallbacks) keep the Rust path.
2. **Text has a cost per label that the spec must budget.** About 30 µs per
   label native, ~150 µs projected on the reference laptop in wasm. A figure
   with more than ~60 labels on screen gets a `check` warning, and
   progressive quality carries it while dragging.

## 4. kinemo facts confirmed

Each was a **(verify)** in SPEC-2.0. Paths are relative to the kinemo
repository at `4cbd012`.

| Claim | Finding | Where |
|---|---|---|
| Frame aspect | `SceneConfig { frame_w, frame_h }`, default 16×9. `FrameSize::scale = width / frame_w`; origin at the centre of the frame. A frame whose `frame_h/frame_w` matches the pixel aspect fills the image exactly. | `kinemo-ir/src/scene.rs:34-36,59-60`; `kinemo-render/src/frame/mod.rs:28-44` |
| Stroke width | Pixels = `stroke_width × height / 1080`, independent of `frame_w`. `dash` scales the same way. | `kinemo-render/src/frame/style.rs:69-72,105-111` |
| Text size | Scene units: pixels = `size × width / frame_w`. Default 0.5. | `kinemo-text/src/types.rs:53-65` |
| Text object | A bare `kind: "text"` leaf draws, with props `text` (Str, with `**bold**`, `*italic*`, `` `code` ``, `$tex$` markup), `size`, `wrap`, `align`, `mono`, `fill`, `fill_opacity` (**must be 1**), `x`, `y`. Centred on its origin. | `kinemo-layout/src/geometry.rs:136,156-169` |
| Maths object | Needs the group form: a `math` object (props `tex`, `size`, `display`, `x`, `y`) whose `children` signal (`Lerp::Layout`) lists one `glyphs` child with `rest: true`, `fill`, `fill_opacity`. A childless `math` draws nothing. Confirmed by rendering in the benchmark. | `kinemo-layout/src/math.rs:12-15`; `glyphs.rs:137-149` |
| Maths needs `typeset` | Without kinemo-math's `typeset` feature (typst), `layout_math` returns `NotBaked` unless a layout was registered with `baked::register`. kinemo's workspace turns `typeset` off; depending on `kinemo-math` directly turns it back on (its default). | `kinemo-math/Cargo.toml`; `cache.rs:40-43`; `baked.rs:57-71` |
| TeX coverage | Anything in mitex's default spec; a corpus test requires ≥ 98% to pass. Covers fractions, roots, scripts, `\left\right`, braces over/under, `\mathbf \mathbb \mathcal \text \operatorname`, accents `\dot \ddot \hat \vec \bar`, Greek, big operators, `\partial \nabla` and the usual relations, and `aligned array bmatrix cases pmatrix vmatrix`. Unsupported commands are an error (K0801), not a silent fallback. | `kinemo-math/src/latex_parser.rs:205-307`; `tests/math_corpus/` |
| Baseline and depth | `MathLayout { bbox, baseline }`; height = `bbox.y1 − baseline`, depth = `baseline − bbox.y0`. Enough to align inline SVG to prose. | `kinemo-math/src/types.rs:42-54` |
| Caching | Text layouts: a **global** cache of 4 096 entries keyed by text, size, wrap, alignment and flags. Maths: a global cache of 2 048 keyed by (tex, size, display). Layout and evaluator memos are per instance. A fresh scene per frame re-uses shaped text. | `kinemo-text/src/cache.rs:10-55`; `kinemo-math/src/cache.rs:11-44` |
| Fonts | DejaVu Sans (regular, bold, oblique) and DejaVu Sans Mono, embedded. Maths uses typst's New Computer Modern, only with `typeset`. | `kinemo-text/src/fonts.rs:7-10`; `kinemo-math/src/world.rs:18-19` |
| `image` kind | Props `src` (a path), `w`, `h`. Bytes can be registered under any name with `media::register_bitmap(path, bytes)`; PNG and JPEG only. | `kinemo-render/src/frame/image.rs:15-18`; `media/bitmap_cache.rs:28-60` |
| SVG export | `render_svg(scene, t, transparent)` renders at `config.width × config.height`; `display_list_to_svg(&DisplayList)`. **Text is emitted as path outlines**, never `<text>`. | `kinemo-render/src/svg.rs:32,44-83,114` |
| Background | `config.background` is painted unless `transparent`; its default is dark. A light theme must set it. Found by looking at the benchmark's PNGs. | `kinemo-render/src/frame/mod.rs:63-65` |

## 5. Things only looking found

Three findings came from opening the PNGs, not from the numbers:

1. **Batched-path heat maps have seams**: a fine dark grid between adjacent
   cells, from anti-aliasing each cell's edge separately. No pixel-count
   test would have caught it.
2. **kinemo's default background is dark**, so `fg` text from a light theme
   vanishes. The theme must set `config.background`.
3. **The maths renders** — fractions, sums, integrals, `pmatrix`, roots —
   once `typeset` is on, and draws nothing at all without it, silently. The
   fourth blank-output default met in this project.

## 6. Changes made

- `crates/hapto-core/examples/m0_rebuild.rs` — the benchmark.
- `crates/hapto-core/Cargo.toml` — `kinemo-math` as a **dev-dependency** only,
  so the benchmark can typeset and the browser build stays free of typst
  (`cargo tree -p hapto-web --target wasm32-unknown-unknown` shows no typst).
  M2 makes this a `typeset` feature of hapto-core, on for the CLI and off for
  hapto-web.
- `docs/SPEC-2.0.md` — updated with every decision above.

## 7. Reproduce

```bash
cargo run --release -p hapto-core --example m0_rebuild   # writes m0-*.png in the cwd

cargo build -p hapto-web --target wasm32-unknown-unknown --profile web
wasm-bindgen target/wasm32-unknown-unknown/web/hapto_web.wasm --out-dir pkg --target web --no-typescript
brotli -q 11 -c pkg/hapto_web_bg.wasm | wc -c
```

The wasm-versus-native timing used a throwaway Node script and a throwaway
crate in `/tmp`; M3's browser benchmark (SPEC-2.0 §19.2) supersedes it.
