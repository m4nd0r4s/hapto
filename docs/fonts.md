# Fonts in the browser build (spike hapto-mn2.2)

M0 measured the browser build at 1.29 MB brotli, of which kinemo-text's four
embedded DejaVu faces were 1.03 MB. SPEC-2.0 §19.1 targets ≤ 0.8 MB.

## What is reachable

All four faces are reachable from the figure format: regular by default,
bold through `weight: bold` (kinemo-text's `**…**`), italic and mono through
the inline markup kinemo-text parses in any text (`*…*`, `` `…` ``). None can
be dropped; each can be cut.

| **all four** | **1 027 378** | 309 130 | **270 189** |

Subset: U+0020–007E, 00A0–017F (Latin-1, Extended-A), 0300–036F (combining),
0370–03FF (Greek), 1D00–1DBF (phonetic super/subscripts: `ᵇ`), 2000–206F,
2070–209F, 20A0–20CF, 2100–214F, 2150–218F, 2190–21FF (arrows), 2200–22FF
(operators), 2300–23FF, 25A0–25FF; all OpenType layout features kept.
Hinting is dropped: kinemo rasterises outlines and never reads it.

`hapto_web.wasm` (profile `web`, no wasm-opt): **1 289 282 → 737 985 bytes
brotli** (5.02 → 3.09 MB raw).

## Does anything render differently?

Every corpus figure and every demo figure, both themes, rendered with the
full and the subset faces: **28 of 28 PNGs byte-identical**, and the corpus
goldens pass. A first cut without U+1D00–1DBF changed one figure (`∫₀ᵇ`), which
is why that block is in.

Maths is unaffected: typst's faces never ship (layouts are baked, §10.4).

## Recommendation

A `subset-fonts` feature on kinemo-text, off by default — kinemo's videos
keep full coverage — that embeds `assets/fonts/subset/*` generated by a
committed `scripts/subset-fonts.sh`. hapto turns it on for every target, so
native renders, goldens and the browser draw the same glyphs.

Rejected: subsetting kinemo's only copy (breaks kinemo users writing other
scripts); a runtime font-override hook (the full faces would still be
linked in unless the hook also gates `include_bytes!`, which is the feature
anyway).

Cost: a character outside the subset draws as the missing-glyph box. A
`check` warning for text outside the subset is a reasonable follow-up.

The change is prepared and validated against hapto (corpus, goldens, byte
comparison, wasm size); landing it is a kinemo commit and a pin bump
(hapto-mn2.3).
